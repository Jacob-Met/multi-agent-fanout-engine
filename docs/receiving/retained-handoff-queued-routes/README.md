## Coverage and limits

The receiver launches the public consumer, public history reader and occupied-output attempt. It checks saved phase receipts/streams, four distinct phase PIDs, state/count/readiness/history at each checkpoint, raw final SQLite event parity, and source/helper/expectation fences.

The candidate-only branch encodes the published contract:

- `initial` routes only ready `summary`, using its native key, model `fixture-local`, effort `low` and pool route source.
- `unknown`, `held` and `final` have no queued-ready routes; unresolved audit and blocked handoff remain explicit where applicable.
- Report order, part/dependency context, counts, project/digest and raw-routing SHA-256 are exact. JSON must be canonical UTF-8 plus one newline.
- Phase CLI arguments, source cwd, status and stream hashes bind the maintained queued-route command and saved report. The final report list retains initial/unknown/held/final order.
- Five unique adapter calls, no audit replay, authored preview, sixteen final events and original artifact bytes remain intact.
- History receiving preserves earlier files and database metadata; occupied output is refused without retained mutation.

The helper does not trace every subprocess or syscall. Some per-phase database-read statements come from the trusted producer and are checked with its reviewed source. File fences cannot exclude transient writes restored before observation. Raw SQLite checks qualify the recorded final observation.

Direct children use owned process groups and bounded communication waits. The original recorded no forced signals and absent groups. Setup failures, group-kill races, escaped descendants, unavailable storage and receipt-write failures need external inspection. This is not a general containment or guaranteed-cleanup framework.

The adapter performs deterministic local file work. Route labels do not establish provider effort behavior, model inference, worker availability or installed estate readiness.
