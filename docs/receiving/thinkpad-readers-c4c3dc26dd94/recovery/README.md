This is an additive evidence companion to the [accepted saved-reader packet](https://drive.google.com/file/d/1uGVv03s4Zz8VBhswRZXu7BrN6Bf_ghQ_/view), not a replacement installation or product build. The existing 245,396-byte corrected packet and its opening-wording correction remain unchanged.

Use the [opening guide](https://drive.google.com/file/d/1itZPwx4T49FyF4NFgbrwvLOyTfGvf8o_/view) for the fictional sample HTML and the [merged operator guide](https://github.com/Jacob-Met/multi-agent-fanout-engine/blob/14de7a0f2449c47e653f62564fc9c2b219fe94dc/docs/receiving/thinkpad-readers-c4c3dc26dd94/README.md) for the already received, ThinkPad-specific `hamon-fanout-read` command. This companion adds no portable virtual environment and performs no installation.

## What became available

The first portable packet carried byte-matched bodies for 69 of the 86 files in the native freeze, with the remaining 17 represented by exact descriptors. Its guide accurately disclosed that activation and installation raw bodies had not survived the earlier cloud memory reset, although their contents had been directly reviewed before the reset.

On 13 October 2026, the existing ThinkPad connection recovered. One read-only process admitted `jacob` UID 1000 on `hamon-thinkpad`, the exact `/usr/bin/python3.14` executable and its SHA-256, then read the 17 missing files from their original paths. Every body matched its original length, SHA-256 and Git blob, and every recorded device, inode, mode, owner, size and nanosecond modification time matched the untouched 86-file freeze before and after the read. The alias descriptor remained inode 450135 with the same target. The native export process 401974 was observed to exit 0 in 0.09 seconds.

The new 17 bodies total 41,899 bytes. They comprise the installation receipt; stage, activation and preflight drivers; connector observations; five durable activation marker/log files; the six inherited help/history observation and stream files; and the installed wrapper. The exact native-export JSON is 69,863 bytes, SHA-256 `c52941a5f8be944803dd9fa978636bf035d1f8e3f43aa54b1ca5d9cbaf5df94f`, Git blob `981efdb972af836fe2829fe76f52a7f2d222877d`. It was stored without a JavaScript numeric round trip.

Together, the original packet and this companion supply byte-corresponding bodies for all 86 frozen files. This is a combined body-coverage statement: only the newly recovered 17 files, the original freeze, executable and alias were freshly inspected during recovery. It is not a new inspection of every installed runtime file.

## Read the evidence

- `raw/installation-receipt.json` preserves the actual installed phase, both inherited-name observations and the 25 runtime identities recorded at installation.
- `raw/activation-job/receipt.json` and its adjacent marker/log files preserve the original helper child 362396, reaped with status 0, receiver status 0, unchanged selected sources and no inspection errors.
- `raw/activation/inherited-help.*` and `raw/activation/inherited-history.*` contain the original actual PATH command observations and complete streams: children 362397 and 362399 both exited 0 and were reaped. These historical commands were not run again.
- `raw/connector-observations.json` preserves the original captured tool responses. `native-start-connector.json` and `native-outer-connector.json` separately preserve the new read-only export responses, including its observed completion.
- `native-recovery.json` is the exact Python-produced body map, with base64, hashes and typed before/after identity records. `ORIGINAL-NATIVE-FREEZE.json` is the untouched original 86-file manifest. `recover_native.py` is the read-only collector; it is retained for review, not an instruction to rerun it.
- `MANIFEST.json` covers every other archive member. The source collector and packaging code are evidence only; no archived code needs to execute to inspect the files.

The former transcript-derived activation checkpoint remains a truthful historical fallback. These recovered original bodies now provide the stronger byte-level record alongside it. No stage, activation, product, browser, withdrawal, live ledger or provider operation was repeated, and no native file was written by recovery.
